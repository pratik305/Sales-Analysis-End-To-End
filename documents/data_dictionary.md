# Data Dictionary
## Maven Fuzzy Factory — Sales & Marketing Analytics

This document describes the curated analytical tables used for reporting and dashboarding.
All tables follow a **star schema design** and are sourced from validated raw data.

---

## 1. FACT TABLES

---

### 1.1 `fact_sales`
**Grain:** One row per order item (product-level transaction)

**Description:**  
Contains all sales transactions at the product level. This is the primary fact table used for revenue, profit, and conversion analysis.

**Source Tables:**  
- `order_items`
- `orders`

| Column Name | Data Type | Description | Source |
|------------|----------|-------------|--------|
| order_item_id | Integer | Unique identifier for each order item | order_items |
| order_id | Integer | Identifier for the order | order_items |
| product_id | Integer | Identifier for the product sold | order_items |
| website_session_id | Integer | Session associated with the order | orders |
| created_at | Timestamp | Timestamp when the order item was created | order_items |
| price_usd | Decimal | Sale price of the product | order_items |
| cogs_usd | Decimal | Cost of goods sold | order_items |
| revenue_usd | Decimal | Revenue generated by the item | Derived |
| profit_usd | Decimal | Profit (revenue − cost) | Derived |
| is_primary_item | Integer | Flag indicating primary item in bundled orders | order_items |

---

### 1.2 `fact_refunds`
**Grain:** One row per refunded order item

**Description:**  
Stores refund transactions associated with order items. Refunds are modeled as a secondary fact table and applied through measures.

**Source Table:**  
- `order_item_refunds`

| Column Name | Data Type | Description | Source |
|------------|----------|-------------|--------|
| order_item_refund_id | Integer | Unique refund identifier | order_item_refunds |
| order_item_id | Integer | Refunded order item | order_item_refunds |
| order_id | Integer | Order associated with refund | order_item_refunds |
| refund_amount_usd | Decimal | Amount refunded | order_item_refunds |
| created_at | Timestamp | Refund timestamp | order_item_refunds |

---

---

## 3. MODELING NOTES

- All fact tables connect **only to dimension tables**, forming a star schema.
- No fact-to-fact relationships are used.
- Refunds are applied via DAX measures, not relationships.
- Time intelligence relies on `fact_sales.created_at` mapped to `dim_date.date`.
- All analytical logic is implemented as **measures**, not calculated columns.

---

## 4. DATA QUALITY ASSUMPTIONS

- Each row in `order_items` represents one unit sold.
- Refund amounts are always associated with a valid order item.
- Session data accurately represents website traffic.
- All timestamps are assumed to be in a consistent timezone.

---

## 5. Intended Usage

This data model is optimized for:
- Executive dashboards
- Marketing performance analysis
- Product and refund analysis
- Time-series reporting

The model is not intended for transactional or operational reporting.
